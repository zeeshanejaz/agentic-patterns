# 21 Agentic Design Patterns

Reference table aligned with [`agentic-design-patterns-docs`](agentic-design-patterns-docs/README.md) (21 patterns, including Model Context Protocol). Video captions that omit MCP: [`transcripts/master-20-agentic-design-patterns.md`](transcripts/master-20-agentic-design-patterns.md).

Each pattern name links to its discussion (when to use, where it fits, pros/cons, examples). Diagrams live in [`mermaid-diagrams`](agentic-design-patterns-docs/mermaid-diagrams/) and [`ascii-art`](agentic-design-patterns-docs/ascii-art/).

Use the tables to pick a pattern. Production systems usually combine several (for example routing + tool use + human-in-the-loop + guardrails).

## Core patterns

| # | Pattern name | Description | When to apply | Pros | Cons |
|---|---|---|---|---|---|
| 1 | [Prompt Chaining](agentic-design-patterns-docs/pattern-discussion/prompt-chaining.md) | Break a complex task into sequential steps. Each step validates the previous output before handing off, then results are merged and artifacts logged. Keep chains short (often 3–5 steps). | Complex multi-step work, data transformation pipelines, quality-critical handoffs, mixed tool/AI operations, and when you need to debug each stage. Fits document processing, ETL, customer-service flows, code generation, content creation. | Modularity; clear failure points; structured contracts between steps; reusable segments; per-step retries. | Latency and cost accumulate; context can be lost or explode between steps; early errors propagate; easy to over-engineer simple tasks. |
| 2 | [Routing](agentic-design-patterns-docs/pattern-discussion/routing.md) | Analyze intent and context, then send the request to the right specialist handler. If confidence is low, ask clarifying questions before routing. | Multi-domain systems, dynamic workflow selection, specialized tool access, confidence-based handling, load balancing. Fits customer service, multi-modal pipelines, enterprise automation, content moderation, healthcare triage. | Specialization; easy to add routes; efficiency; clear separation of concerns; independent maintenance per path. | Router can become a bottleneck; misrouting; extra decision latency; edge cases that fit no category; monitoring many paths. |
| 3 | [Parallelization](agentic-design-patterns-docs/pattern-discussion/parallelization.md) | Split independent work across concurrent workers, then normalize, merge, and keep provenance of which worker produced which part. | Large-scale data, time-sensitive independent tasks, batch jobs, multi-source scraping or API aggregation, multi-document analysis. Fits document pipelines, enrichment, research automation, testing. | Speed; better resource use; scale workers up or down; fault isolation between workers. | Coordination and merge complexity; rate limits; harder debugging; cost and memory multiply; ordering is extra work. |
| 4 | [Reflection](agentic-design-patterns-docs/pattern-discussion/reflection.md) | Generate a draft, have a critic score it against a rubric or tests, then revise until it meets the bar or hits a max retry count. | Quality-critical output, complex reasoning, creative work that needs polish, compliance standards, error-prone domains. Fits content, code generation, legal drafting, academic writing, product descriptions. | Systematic quality improvement; generation and critique stay separate; consistent standards; a feedback trail. | Extra latency and cost; diminishing returns; API throttling; over-optimization can flatten voice; needs a hard stop. |
| 5 | [Tool Use](agentic-design-patterns-docs/pattern-discussion/tool-use.md) | When the agent needs external data or actions, discover tools, check permissions, call the right one with correct parameters, parse the result, and fall back on failure. Also called function calling. | External/real-time data, system integration, precise computation, file operations, concrete actions, multi-step workflows that mix reasoning with tools. Fits research, data analysis, DevOps, customer service, content management. | Capabilities beyond text; live data; deterministic precision; end-to-end automation; auditable tool calls. | Security and credential risk; a bad or “successful but wrong” call poisons later steps; extra latency and dependency on external services. |

## Advanced patterns

| # | Pattern name | Description | When to apply | Pros | Cons |
|---|---|---|---|---|---|
| 6 | [Planning](agentic-design-patterns-docs/pattern-discussion/planning.md) | Decompose a goal into milestones and a dependency graph, check constraints, assign agents and tools, then execute while tracking progress. Replan or escalate when the environment changes. | Multi-step projects with dependencies, goal-oriented work, resource limits, uncertain environments, long-running or collaborative tasks. Fits project automation, software delivery, research, content series, business workflows. | Strategic (proactive) execution; dependency handling; resource allocation; adaptability; visible milestones. | Upfront planning latency; over-planning can freeze flexibility; prediction errors; replanning cost; coordination overhead. |
| 7 | [Multi-Agent Collaboration](agentic-design-patterns-docs/pattern-discussion/multi-agent-collaboration.md) | Specialized agents work different parts of a complex task under a coordinator, often sharing structured memory, artifacts, and acceptance criteria. | Multi-faceted problems, parallel workstreams, specialized knowledge, scale via division of labor, iterative refinement from multiple perspectives. Fits software teams, content pipelines, financial analysis, customer service, research. | Specialization; parallel processing; modular agents; robustness if one agent fails; domain boundaries. | Coordination and shared-context cost; more API spend; debugging across agents; conflicts and state sync. |
| 8 | [Memory Management](agentic-design-patterns-docs/pattern-discussion/memory-management.md) | Classify information as short-term, episodic, or long-term; store it with recency/relevance metadata; retrieve and update without overflowing the context window. | Conversational continuity, personalization, learning over time, multi-step state, multi-turn sessions. Fits support bots, personal assistants, tutors, project context, research across sessions. | Context preservation; tailored responses; less repeated work; more natural multi-turn UX. | Storage and privacy; retrieval quality; stale memories; context-window limits; sync across systems. |
| 9 | [Learning and Adaptation](agentic-design-patterns-docs/pattern-discussion/learning-and-adaptation.md) | Collect corrections, ratings, and outcomes; clean noise; update prompts, policies, examples, or (rarely) weights; then A/B test whether the change helped. | Performance that should improve with use, personalization, error reduction, domain specialization, dynamic environments with user feedback. Fits support, recommendations, code assistants, education, decision support. | Continuous improvement; personalization; fewer repeated mistakes; better alignment with users. | Feedback quality and volume; training cost; regressions; poisoning / learning the wrong lesson; concept drift. |
| 10 | [Model Context Protocol](agentic-design-patterns-docs/pattern-discussion/model-context-protocol.md) | Standardize how agents discover and call tools, data, and services: one protocol for auth, versioning, and observability instead of one-off integrations. The 21st pattern; the video summary skipped it as already widely covered. | Enterprise-scale apps, many external resources, consistent interfaces, access control, changing resources, interoperability across AI systems. Fits enterprise platforms, multi-vendor/cloud, microservices, API gateways. | Universal interface; dynamic discovery; built-in auth; versioning; reuse across agents; enterprise-grade ops. | Upfront protocol work; extra abstraction and latency; learning curve; migration of existing tools; needs ecosystem support. |

## System patterns

| # | Pattern name | Description | When to apply | Pros | Cons |
|---|---|---|---|---|---|
| 11 | [Goal Setting and Monitoring](agentic-design-patterns-docs/pattern-discussion/goal-setting-and-monitoring.md) | Define measurable goals (deadlines, budgets, KPIs), run quality gates, compare progress to targets, and adjust resources, plan, or scope when the system drifts. | Autonomous work toward objectives, complex projects, resource/SLA constraints, strategic alignment with business goals. Fits project automation, sales pipelines, publishing schedules, system optimization, cost control. | Purpose-driven work; self-assessment; early warning; accountable metrics; efficient allocation. | Extra machinery; rigid constraints; hard-to-quantify goals; metric gaming; goal conflicts. |
| 12 | [Exception Handling and Recovery](agentic-design-patterns-docs/pattern-discussion/exception-handling-and-recovery.md) | Catch failures, classify temporary vs permanent, retry with capped backoff, degrade to fallbacks, and emergency-stop plus alert on critical errors. Pair with every other pattern in production. | Production reliability, external APIs, operations that must not fail closed, unpredictable input, network and quota issues. Fits API integrations, data pipelines, user-facing and financial systems, IoT. | Continues through failure; graceful degradation; self-healing of transients; better UX and debug logs. | Code and infra complexity; retry latency; false positives; alert fatigue; poorly designed retries can cascade. |
| 13 | [Human-in-the-Loop](agentic-design-patterns-docs/pattern-discussion/human-in-the-loop.md) | At high-risk, low-confidence, compliance, or edge-case points, pause for a human to approve, edit, deny, or take over, then resume. | High-stakes decisions, required oversight, QA, unusual cases, collecting training feedback, gradual automation. Fits content moderation, medical verification, financial approvals, legal review, hiring. | Human judgment on errors; compliance; a learning signal; trust and accountability; edge-case coverage. | Throughput and cost limits; wait time; inconsistent reviewers; fatigue; 24/7 coverage. |
| 14 | [Knowledge Retrieval (RAG)](agentic-design-patterns-docs/pattern-discussion/knowledge-retrieval-rag.md) | Parse, chunk, and embed documents; retrieve top-k (optionally rewrite/rerank); generate a grounded answer with citations. Tune chunking and k so extra matches do not invite hallucination. | Dynamic or large corpora, domain knowledge, factual accuracy, citations, reducing hallucination. Fits enterprise search, support, research, legal, technical docs. | Grounded, citable answers; scalable knowledge; easier to update than the prompt; less fabrication. | Vector/index infrastructure; chunking and retrieval quality; extra latency; maintenance as the corpus grows. |
| 15 | [Inter-Agent Communication](agentic-design-patterns-docs/pattern-discussion/inter-agent-communication-a2a.md) | Agents talk through structured messages (A2A) with IDs, expiry, auth, and conflict rules. Topologies include a coordinator, peers, or a shared board. Cap loops and drop stale messages. | Complex multi-agent workflows, composable/distributed agents, collaboration, service-oriented agent design. Fits enterprise automation, research, content production, trading, smart-city systems. Prefer simpler designs unless you have dedicated engineering. | Modularity; scale by adding agents; fault isolation; message tracing; parallel work. | Protocol complexity; message latency; hard distributed debugging; consistency and security between agents. |

## Optimization patterns

| # | Pattern name | Description | When to apply | Pros | Cons |
|---|---|---|---|---|---|
| 16 | [Resource-Aware Optimization](agentic-design-patterns-docs/pattern-discussion/resource-aware-optimization.md) | Classify task complexity and route simple work to cheap/fast models and hard work to expensive ones. Monitor tokens, time, and spend; fall back to cache, shorter context, or cheaper models. | Cost-sensitive or high-volume work, variable difficulty, budget caps, speed-vs-cost tradeoffs, multi-tenant fairness. Fits SaaS, batch jobs, prod cost control, cheaper models in dev. | Lower API/compute cost; right-sized quality; more predictable budgets; room to grow. | Routing overhead; quality varies by model; threshold tuning; cache coherency; uneven latency. |
| 17 | [Reasoning Techniques](agentic-design-patterns-docs/pattern-discussion/reasoning-techniques.md) | Choose a method for the problem: chain-of-thought, tree-of-thought (branch/prune), self-consistency, or adversarial debate. Score candidates against a rubric. Advanced; skip for most everyday tasks. | Multi-step logic, math, strategy, critical analysis, systematic decisions, creative exploration of options. Fits research, debugging, business strategy, medical differential diagnosis, legal argument. | Higher accuracy; inspectable traces; multiple paths; method matched to the problem. | Latency and tokens; overthinking simple work; context limits; cost of many paths; diminishing returns. |
| 18 | [Guardrails/Safety Patterns](agentic-design-patterns-docs/pattern-discussion/guardrails-safety-patterns.md) | Check inputs for harm, PII, and injection; classify risk; apply controls (block, constrain, sandbox, human review); moderate outputs against policy, compliance, and brand. Catch issues upstream. | Public-facing systems, regulated industries, brand and privacy, security, ethical constraints. Fits chatbots, generated content, healthcare, finance, education. Open text boxes are a common attack surface. | Fewer harmful outputs; compliance; brand and user protection; audit trail of safety decisions. | False positives; extra latency; user friction; policy maintenance; missed nuance; processing cost. |
| 19 | [Evaluation and Monitoring](agentic-design-patterns-docs/pattern-discussion/evaluation-and-monitoring.md) | Set quality gates and golden tests before deploy. Continuously watch accuracy, SLAs, cost, and drift; alert and audit on regressions. This is infrastructure, not something a model sets up by itself. | Production reliability, QA, compliance, performance and cost tracking, data-driven improvement. Fits enterprise, SaaS, healthcare, finance, e-commerce. | Early issue detection; visible quality/cost; audit trails; metrics that guide optimization. | Monitoring infra; alert fatigue; storage and instrumentation overhead; stale tests; false rollbacks. |

## Strategic patterns

| # | Pattern name | Description | When to apply | Pros | Cons |
|---|---|---|---|---|---|
| 20 | [Prioritization](agentic-design-patterns-docs/pattern-discussion/prioritization.md) | Score tasks on value, risk, effort, urgency, and dependencies. Execute the top item, then re-score — the first action can change what should happen next (triage, not a static list). | Limited capacity, competing goals, changing environments, dependencies, deadlines, fair scheduling. Fits task systems, support queues, manufacturing, healthcare triage, DevOps. | Better resource use; urgent work first; fairness if aging is applied; transparent ranking; adapts as conditions change. | Scoring complexity; reorder overhead; starvation of low-priority work; context switching; subjective or unstable scores. |
| 21 | [Exploration and Discovery](agentic-design-patterns-docs/pattern-discussion/exploration-and-discovery.md) | Search broadly across papers, data, and experts; cluster themes; score novelty, impact, gaps, and feasibility; deep-dive the best leads; synthesize insights and next steps. | New domains, innovation, mapping a problem space, knowledge gaps, competitive analysis, hypothesis-driven research. Fits R&D, academia, market research, drug discovery, tech scouting. | Finds what is worth pursuing; broad coverage; hidden connections; structured exploration. | Slow and compute-heavy; uncertain payoff; scope creep; information overload; hard to decide where to focus. |

## Combining patterns

These are building blocks, not mutually exclusive choices:

- **Routing** often sits in front of **tool use** and specialist agents.
- **Prompt chaining** and **planning** both sequence work; chaining passes outputs along, planning tracks a goal graph.
- **Model Context Protocol** is the integration layer under **tool use** (and often multi-agent setups) when tools must be discovered and authorized consistently.
- **Reflection**, **evaluation and monitoring**, **guardrails**, **exception handling**, and **human-in-the-loop** are quality and safety layers on top of other patterns.
- **Memory management** and **learning and adaptation** support long-running, personalized systems.
- **Resource-aware optimization** can wrap any of the above when cost matters at volume.
- **Inter-agent communication** is how **multi-agent collaboration** talks; start with a coordinator before a full peer mesh.
